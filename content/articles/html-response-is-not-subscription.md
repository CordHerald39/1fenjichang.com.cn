## 先确认下载到的是不是配置

导入提示 unexpected token、缺少 proxies 或文件无法解析时，不要立即修 YAML。服务器可能返回了登录页、验证页或错误页，客户端却把它当配置解析。HTTP 200 也只说明请求成功返回，不能证明正文是有效订阅。

## 在本机查看最少信息

先从客户端日志取得状态码、错误类型与时间，遮住 URL 查询参数。若客户端允许预览原始内容，只看开头是否为 HTML 标签、网页标题或登录表单；不要公开贴出正文。某些合法订阅可能是链接列表或编码文本，格式要与目标客户端要求对应。

## 按响应情况分开处理

返回登录页时，从你已核实的账户入口重新获取专门的客户端订阅链接，不使用浏览器地址栏里的账户页面。401 或 403 应先检查授权、令牌与访问限制；404 检查地址是否过期或复制不完整；429 停止连点更新，按响应提示等待。不要通过自动重试绕过限制。

| 看见的内容 | 应核对的项目 |
| --- | --- |
| HTML 登录页 | 是否误复制账户页面 |
| HTML 验证页 | 服务是否支持客户端直接获取 |
| 空正文 | 状态码、网络、服务端错误 |
| 配置有内容但不能解析 | 输出格式与内核版本 |

## 重定向也要有边界

HTTPS 链接若跳往陌生域名，先核实服务方说明，不跟随来历不明的“最新地址”。下载配置与账户登录可能属于不同路径，但合理差异也需要证据。不要为了解决导入而把令牌提交到公开转换器，或关闭 TLS 证书校验。

重新获取后只导入一份，确认节点列表存在，再进行连接检查。教程入口见[导入订阅](/tutorials/import-subscription/)和[订阅安全](/tutorials/subscription-safety/)。

## 依据

[MDN 401 状态码](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/401)、[MDN 429 状态码](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/429)解释 HTTP 响应；[curl 手册](https://curl.se/docs/manpage.html)说明响应与重定向。本文不宣称某个服务当前出现这些故障。
